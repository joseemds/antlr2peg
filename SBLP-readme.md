# ANTLR2PEG

ANTLR2PEG is a tool that converts ANTLR4 grammars into PEG grammars usable with
`lpeg`

## Paper

This artifact accompanies the paper *ANTLR2PEG: A tool to convert ANTLR grammars into PEGs
grammars*, accepted at
CBSoft 2026 / SBLP 2026. The paper is available at: [./paper/antlr2peg.pdf].

## Repository Structure
```
├─ converter/        # ANTLR2PEG source code (Java)
├─ scripts/ 
├─ grammars/ 
├─ generated_tests/ 
├─ LICENSE
├─ Dockerfile
└─ README.md
```

- `converter/` — ANTLR2PEG source code, written in Java.
- `grammars/` — 10 grammars used for deeper analysis, together with their respective examples for testing
- `scripts/` — Helpers to generate and run tests using grammarinator, written in Python 
- `generated_tests/` — Tests generated by grammarinator and used to benchmark results

## Requirements

### Software environment

ANTLR2PEG was tested using Linux, we expect it to work flawless on other UNIX environments.

ANTLR2PEG dependencies are listed below. We also provide a Dockerfile that setups a working environment to run
the tool and all benchmarks

### Dependencies

- Java 21 (Required to build and run ANTLR2PEG)
- Lua >= 5.3 (Required to run the generated PEG parser)
- make (Required to build ANTLR2PEG more easily)
- lpeglabel > 1.0 (Required to run the generated PEG parser)
- grammarinator == 26.1 (Only required to generated new tests)
- python > 3.11 (Required to run scripts for benchmarks and testing)

## Installation

To simply run and build the tool, only Java is enough 

### Build

To build ANTLR2PEG run on the root folder:

```bash
make deps && make jar
```
After that, you can use the helper `antlr2peg` to run the tool.


### Running the tool

As input, an ANTLR grammar is required, the grammars used for deeper analysis are avaible under (./grammars/)[./grammars/] and can be used for testing purposes

The syntax to run `antlr2peg` is:

```bash
# For a single file
./antlr2peg -i grammar.g4 -o grammar.lua

# For separated lexer and grammar
./antlr2peg -l lexer.g4 -g grammar.g4 -o grammar.lua
```

### Running the generated parser

To run the generated test, it is required to have Lua (>= 5.3) installed together
with the `lpeglabel` library, which can be installed with:

```bash
luarocks install lpeglabel
```

First, we need to generate a PEG parser using the command stated before, left use the `abnf` grammar available under (./grammars/abnf/Abnf.g4)[./grammars/abnf/Abnf.g4]

```
./antlr2peg -i ./grammars/abnf/Abnf.g4 -o abnf.lua
lua abnf.lua < ./grammars/abnf/examples/iri.abnf
# Expected: Parsed: 1881
```

### Using Docker

Instead of downloading all dependencies and building the project locally, ANTLR2PEG can also be used using Docker, by running:

```
docker build --target dev antlr2peg .
docker run -it --rm antlr2peg:dev
```

This will drop you into a shell will all dependencies needed to run both ANTLR and the benchmarks described below.


## Running the benchmarks

To run the benchmarks, it is necessary to have `python`and `antlr4-tools` installed. You can install it with:

```
# We recomend to use a virtual env
pip install -r Requirements.txt

```

Before running any benchmark, it is important to generate all PEG parsers and gather some necessary metadata.
To do this, all you need to do is run `make benchmark` on the root of the project.

After the command succeeds, a `results.json` file will be created inside the `converter/` directory, which will be needed to run our tests.

### Testing the PEG parsers against its examples
To run all PEG parsers against their examples available from antlr/grammars-v4 repo, you can run:

```
./scripts/benchmark_examples converter/grammars.json converter/results.json -o examples_results.json
```

If you want to specify one or more grammars, you can do it by passing the flag `--only`

```
./scripts/benchmark_examples converter/grammars.json converter/results.json --only abnf, dot

```

### Testing the agreement of the ANTLR and PEG parser for each grammar
To run and compare the results between the PEG parser and the ANTLR parser against the generated output, you can run:

```
./scripts/run_all_grammars converter/grammars.json  converter/results.json generated_tests/ -o generated_results.json
```

## Analyzing results

Our benchmark creates JSON files with the gathered data. To analyze it, we use the (jq)[https://jqlang.org/] tool.

We describe how to generate this data on the previous section. However, if you want to check the data without running the tests again, we have them available as:

`results.json`: Results from generating the PEG parsers, showing wheter it succeed or failed (with the reason to the failue)
`examples_results.json`: Results from testing all generated PEG parsers against their examples
`generated_results.json`: Results from testing all generated PEG parsers against their examples

We have a few scripts to visualize each result better, you can run them as follow:

```bash
# To summarize which grammars generated a PEG parser successfully
# These are the results from table 1
./scripts/summary_results converter/results.json

# To summarize how many PEG parsers recognized all of their examples
# These are the results from table 2
./scripts/summary_example_benchmark examples_results.json 

# To summarize the agreement of each PEG parser with their respectice ANTLR parser
# These are the results from table 3
./scripts/summary_generated_benchmark  generated_results.json

# To summarize which transformations where applied to each of the 10 analyzed grammars
# These are the results from table 4
./scripts/fetch_10_grammars converter/results.json
```
